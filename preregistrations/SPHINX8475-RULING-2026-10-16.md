## 1. Ruling

**Primary: score the four errored (instance, arm, seed) cells as attempted and unresolved.** Pairing, the
n = 500 / 478 instance sets, and the exact decomposition are untouched. This is done under a general,
pre-registered-now classification rule (§4) that also binds TM and B3.

**Two sensitivities, pre-registered here and reported beside every §7.1 contrast and the §8/§9 verdicts:**
(A) the literal §6 reading, sphinx-8475 removed from every arm and seed (the agent's option i); (B) the
extreme opposite bound, the four cells scored as resolved. The instance can move any pooled Δ by at most
3/1500 = 0.20 pp (0.21 pp on the 478 set) and any per-seed McNemar b or c by at most 1. If any verdict or
prediction (§8, §9) differs between the primary and either sensitivity, the paper reports the primary and
states in the same sentence that it is not robust to the handling of this one instance; no verdict is
upgraded by the choice.

**Rejected: regrading with a longer `--timeout` (option iii).** The hang is a deadlock, not a slow test (§2).
No finite timeout terminates it. It would cost ≥ 4 × 30 min of Docker time for a result that is known.

Trade-offs between the primary and (A) are stated in §3. If the owner prefers the minimal-deviation reading of
the pre-registration, (A) as primary with the scored variant as sensitivity is acceptable; the §12 text in §7
then needs only its "Primary" and "Sensitivity A" labels swapped. (iii) is not acceptable in either case.

## 2. What actually happened (corrects the executor's causal account)

The executor's log attributes the hang to "a requests GET fallback in linkcheck (likely network calls inside
the test)". That is not the mechanism, and the difference matters because it determines whether a longer
timeout could ever help.

**The environment is sound and network is live.** The gold patch, run in the same image in the same Docker
session (`run_id b1b3_gold_sphinx8475`), passed all 18 tests with a test runtime of **3.11 s** (the "about 2
minutes" in §12 is the container lifecycle). Its captured test output shows the fixture's live URLs answering
normally (`https://www.google.com/image.png: 404 Client Error`, w3.org and sphinx-doc.org `ok`), so the
container reaches the network and the tests that need it finish in seconds.

**The four model patches deadlock the linkcheck builder.** At base commit `3ea1ec84`,
`sphinx/builders/linkcheck.py` runs `linkcheck_workers` daemon threads whose loop is

    while True:
        uri, docname, lineno = self.wqueue.get()
        if uri is None: break
        status, info, code = check(docname)          # no try/except
        self.rqueue.put((uri, docname, lineno, status, info, code))

and the main thread waits in `write_doc` with

    while done < n:
        self.process_result(self.rqueue.get())       # no timeout
        done += 1

Any exception that escapes `check_uri` kills that worker; the result for that link is never posted, and the
main thread blocks on `rqueue.get()` forever. The four patches each insert a HEAD/GET block at the top of
`check_uri`, inside the `try: req_url.encode('ascii')` guard (which catches only Unicode errors) and before
the original `try/except Exception` that protects the real request. By code inspection:

| cell | inserted code | first uncaught exception | needs network? |
|---|---|---|---|
| ON s00 | `requests.head(req_url, **kwargs)`, fallback `requests.get`, then `raise` | `ConnectionError` re-raised on the fixture's refused link `https://localhost:7777/doesnotexist` | no (refused socket) |
| OFF s02 | bare `head(req_url, config=self.config, **kwargs)` | `NameError: head` on the first URL (`head` is not imported; the module imports `requests` from `sphinx.util`) | no |
| T s00 | `requests.head` + `raise_for_status`, fallback, `return 'broken', str(resp.reason), …` | `UnboundLocalError: resp` on the refused link (the `except` reads `resp` before it is assigned) | no |
| T s01 | `self.session.head(…, timeout=self.timeout)` | `AttributeError: session` on the first URL (`Builder` has no `session`) | no |

Every one fires before the original request logic runs. Each is deterministic; none depends on the network,
on `max_workers` (passes 1–2 used 6, pass 3 used 1), or on load. The test output of every hung run shows
`collected 18 items`, then `tests/test_build_linkcheck.py ` with **zero progress markers**, then
`Timeout error: 1800 seconds exceeded.`: the first test never returns. 12 of 12 passes agree.

**Consequences.** (1) The grade is determinate: under these patches the FAIL_TO_PASS test
`test_TooManyRedirects_on_HEAD` cannot be observed passing (the process never gets there, and the same
inserted block would kill the worker on that test's URL too). `resolved = all F2P pass ∧ all P2P pass` is
false with certainty. (2) The harness's own report already encodes this: its headline rate is
`resolved_instances / total_instances`, so an errored instance counts as not resolved in the number the
harness prints. (3) The §6 premise "harness errors are infrastructure failures, never model failures" is
false for this instance, and it is the registered diagnostic (gold-pass in the same environment, three
identical passes) that shows it.

## 3. Why the primary is "score as unresolved", and the trade-offs

**What §6 actually says.** "If an instance errors deterministically in 3 consecutive passes with the same
cause, stop and log a deviation. It is not scored." The clause anticipated this situation and prescribed a
stop plus a deviation ruling; "not scored" is the default pending that ruling. §7.1 then defines pooled
estimates "on the common set", and a cell that is not scored drops the (instance, seed) from the common set.
Applied literally, sphinx-8475 is unscored at seed 0 (ON), seed 1 (T) and seed 2 (OFF), so the common-set rule
removes it from the decomposition at all three seeds: the literal reading **is** option (i). It is therefore a
legitimate, pre-registered-compatible choice, and that is why it is sensitivity A rather than rejected.

**Why not make it primary.** Exclusion here is post-treatment selection. Whether a model writes a hanging patch
is a property of its output, and its propensity may differ by arm (the hangs are 1 ON, 1 OFF, 2 T; nothing
about that pattern is readable as favouring any prediction, and I have not looked). Dropping the instance
discards five real, cleanly graded cells and four cells whose true grade is known, because of the content of
the model's patches. The paper's own review history (the methodology reviewer audit, TRIMMED-BREADTH's withdrawal of
error-contaminated T analyses) is sensitive to exactly this kind of selection, and a reviewer reading "we
removed an instance where our model broke the test suite" will weight it accordingly, even at 0.2 pp.

**Why scoring is not a violation of §6's purpose.** §6 exists so that infrastructure noise is never recorded
as model failure (the TRIMMED-BREADTH lesson: 429 pulls "deflate T"). Scoring a deterministic, patch-induced
deadlock as unresolved records a model failure as a model failure. It treats a hanging patch exactly as §6
already treats an empty patch: submitted, attempted, not resolved. It keeps every registered set intact. It is
the same grade the harness's own summary rate assigns. And the classification uses only outcome-free evidence
(error ids, the gold run, the patch text, the hung test output, the source), applied before anything is read.

**The cost, stated plainly.** It is a deviation from the sentence "never model failures ... It is not scored",
made after the error was observed. Pre-registration exists to prevent post hoc scoring changes, and a
reviewer may say so. The mitigations are: the rule is general and fixed now for TM and B3 before their errors
(if any) exist; both alternatives are reported; the maximum leverage is 0.2 pp against a ±3 pp TOST margin and
a headline-scale effect of several pp; and the deviation is logged with its mechanism. The prior ruling's
principle applies: when a registered check shows the rule's premise does not hold, the purpose governs and the
deviation is logged.

**Why not (iii), beyond futility.** Even if the hang were a slow network wait, the gold run's 3 s against 1800 s
is a factor of 600; no defensible timeout exists. And a successful regrade under a different timeout would
grade four cells under a different harness setting from the other 4,000-odd cells, which is its own deviation.

## 4. The rule (binding for B1, B2/TM and B3/P; pre-registered here before any TM or P error exists)

A harness error that survives §6's retry passes (same cause in 3 consecutive passes) is classified, before any
outcome is read, into exactly one class using only: the report's `error_ids`, the run's `run_instance.log`
and `test_output.txt`, the cell's `patch.diff`, a gold-patch run of the same instance in the same environment,
and source inspection.

- **Class I (infrastructure).** Any of: the error is in image pull/build, container start, Docker, DNS,
  memory or disk; **or** the gold patch also errors or hangs in the same environment and session; **or** the
  cause cannot be located in the model patch. Handling as registered: never scored, regrade; if it cannot be
  cleared, stop and refer. The gold-pass test is the same instrument CONTAMINATION-PREREG's gold gate uses to
  decide whether an instance is gradable at all.
- **Class P (patch-induced).** All of: the patch applied; the gold patch resolves the instance in the same
  environment and session; the failure reproduces identically in 3 consecutive passes; and the mechanism is
  located in the model patch (here: an uncaught exception in a worker thread leading to an unbounded wait).
  Handling: **the cell is scored as attempted and unresolved** (primary), and the two sensitivities of §1 are
  reported. The classification evidence is logged per cell in §12.

The harness `--timeout` stays at 1800 s for every arm. No cell is regraded under a different setting.

**B3 eligibility (§5).** "every B1 and B2 file is fully graded (0 harness errors)" is read as "0 unclassified
or Class-I harness errors". A Class-P cell is fully graded (its grade is determinate). Under the literal
reading the four B1 files would carry `error_instances = 1` forever and B3 could never run, which the
condition did not intend (it guards against analysing while grading is unfinished). Current timing: TM s01/s02
grading finishes about 13:30 EDT today; P generation (~45 min) plus grading fits well inside the 2026-10-18
21:00 EDT deadline.
